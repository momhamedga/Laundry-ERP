# نظام إعداد التشغيل (Runtime Configuration)

> Phase 15C · يُنشأ تلقائياً عند أول تشغيل · لا يحتاج أي تدخّل من العميل

---

## 1. لماذا وُجد

الـ API يقرأ إعداده عبر `dotenv/config` من **مجلّد عمله**. في التطوير مجلّد
العمل هو `apps/api` وفيه `.env`؛ بعد التثبيت هو `resources/api` وليس فيه شيء —
فيرفض التحقّق ثلاثة متغيّرات ويخرج، ويعيد المدير المحاولة ستّ مرّات ثم يستسلم،
فيبقى التطبيق ميتاً بلا تفسير.

نظام إعداد التشغيل يحلّ ذلك: إعداد حقيقي **خارج مجلّد التثبيت**، يُنشأ تلقائياً،
ويُمرَّر للـ API كبيئة عملية — بلا أي ملفّ داخل مجلّد البرنامج.

---

## 2. الموقع

```
%APPDATA%\@laundry\runtime\      ← الإعداد والأسرار
%APPDATA%\@laundry\desktop\      ← بيانات التطبيق وقاعدة SQLite المشفّرة
```

### لماذا خارج `userData`؟

| السبب | التفصيل |
|---|---|
| **الأمان** | `userData` هو ما تنسخه خدمة النسخ الاحتياطي. لو وُضعت الأسرار هناك لسافر رابط قاعدة البيانات وأسرار JWT داخل كل ملفّ نسخة يُرسل بالبريد أو يُنسخ على فلاشة |
| **إلغاء التثبيت** | إلغاء التثبيت للمستخدم الحالي لا يمسّ `%APPDATA%` ⇒ إعادة التثبيت لا تحتاج إعادة تجهيز |
| **التحديث** | خارج مجلّد التثبيت ⇒ لا يتأثّر بأي تحديث |
| **الدعم الفني** | مسار واحد معروف، يُفتح من **مساعدة ← عن التطبيق ← فتح مجلّد الإعداد** |

> **تحفّظ:** `%APPDATA%` هو Roaming. على أجهزة مرتبطة بدومين قد يُزامَن ضمن ملفّ
> تعريف المستخدم. مقبول لأن قاعدة البيانات المشفّرة نفسها في Roaming، والمجلّد
> محصور بصلاحيات المستخدم.

## 3. الملفّات

### `server.env` — بيئة الـ API ⚠️ يحتوي أسراراً

```env
NODE_ENV=production
PORT=4000
DATABASE_URL=postgresql://…        ← من التجهيز
JWT_ACCESS_SECRET=…                ← يُولَّد محلّياً
JWT_REFRESH_SECRET=…               ← يُولَّد محلّياً
```

الأسرار تُولَّد بـ `crypto.randomBytes(48)` → 64 حرفاً (الحدّ المطلوب 32).
**مختلفة لكل تثبيت.** لا تُشحن ولا توجد في أي حزمة.

### `runtime.json` — إعداد غير سرّي

```json
{
  "schemaVersion": 1,
  "installId": "uuid",
  "createdAt": "…", "updatedAt": "…",
  "apiPort": 4000, "rendererPort": 3100,
  "lastAppVersion": "2.0.0"
}
```

### `installation.json` — هوية التركيب

اسم العميل والمغسلة والهاتف والفرع ورقم الترخيص وتاريخ التركيب. **بلا أسرار.**

### `branding.json` — تخصيص العميل (اختياري)

يعلو على الهوية المُغلَّفة، فيمكن تخصيص عميل بلا إعادة بناء.

### `provision.applied.json` — أرشيف التجهيز

ملفّ التجهيز بعد استهلاكه. يُحتفظ به للتشخيص.

## 4. دورة الحياة

```
أول تشغيل
   ├─ إنشاء المجلّد + تقييد الصلاحيات (icacls)
   ├─ إن وُجد provision.json ⇒ استهلاكه ثم أرشفته
   ├─ توليد أسرار JWT (إن غابت)
   ├─ كتابة runtime.json و installation.json
   └─ فحص الاكتمال ⇒ تشغيل الـ API أو عرض حوار «غير مُجهَّز»

كل تشغيل تالٍ
   └─ idempotent تماماً: لا يُعاد توليد سرّ موجود ولا تُلمس قيمة مضبوطة
```

**لماذا الثبات مهمّ؟** لو أُعيد توليد أسرار JWT عند كل تحديث لأُبطلت كل جلسات
المستخدمين وطُلب منهم تسجيل دخول جديد بعد كل ترقية.

**زمن التهيئة المقيس:** 1–24 ملّي ثانية.

---

## 5. الأمان

- الأسرار تُولَّد محلّياً بـ `crypto.randomBytes` — **لا تُشحن أبداً**.
- `provision.json` يحمل رابط القاعدة فقط، **لا أسرار JWT**.
- المجلّد يُقيَّد بـ `icacls /inheritance:r` + منح المستخدم وحده.
- `server.env` يُكتب بصلاحيات `0600`.
- **مُتحقَّق:** لا سرّ حيّ ولا `postgres://` داخل `app.asar`، ولا شيء منها في السجلّات.

## 6. التشخيص

| العَرَض | السبب | الحل |
|---|---|---|
| «لم يكتمل تجهيز هذا الجهاز» | لا `DATABASE_URL` | اضغط «استيراد ملفّ التجهيز» واختر `provision.json` من الحزمة |
| الـ API لا يقلع رغم التجهيز | رابط قاعدة خاطئ | افحص `server.env` وجرّب الاتصال من أداة خارجية |
| فقد الإعداد بعد نقل الجهاز | نُسخ مجلّد التثبيت بلا `%APPDATA%` | أعد تشغيل `تثبيت وتجهيز.cmd` |
| جلسات المستخدمين تنتهي بعد كل تشغيل | `server.env` غير قابل للكتابة | افحص صلاحيات المجلّد |

### أوامر مفيدة

```powershell
# فتح مجلّد الإعداد
explorer "$env:APPDATA\@laundry\runtime"

# المفاتيح المعرّفة (بلا قيم)
Get-Content "$env:APPDATA\@laundry\runtime\server.env" |
  Where-Object { $_ -match '^[A-Z_]+=' } | ForEach-Object { ($_ -split '=')[0] }
```

> ⚠️ لا ترسل `server.env` للدعم الفني — يحتوي أسرار جهازك. أرسل بدلاً منه
> **«عن التطبيق ← نسخ بيانات الدعم»**.
