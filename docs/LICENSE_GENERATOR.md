# مولّد التراخيص — دليل المطوّر

> ⚠️ **أداة داخلية. لا تُشحن للعملاء أبداً. تحتوي المفتاح الخاص.**

الموقع: `tools/license-generator/`

---

## 1. الإعداد لأوّل مرّة

```bash
cd tools/license-generator
pnpm install
pnpm run build
```

### توليد زوج المفاتيح — مرّة واحدة في عمر المنتج

```bash
node dist/cli.js keygen
```

يُنتج:

```
keys/private-key.pem     ⚠ سرّي — لا يغادر جهازك أبداً
keys/public-key.pem      يُدمج في التطبيق
```

ثم انسخ المفتاح العام إلى التطبيق:

```
apps/desktop/src/main/license/public-key.ts
```

> **`keys/` و`issued/` متجاهلتان في Git** عبر `tools/license-generator/.gitignore`.
> تحقّق دائماً قبل أي التزام:
> ```bash
> git check-ignore -v tools/license-generator/keys/private-key.pem
> ```

### 🔴 القاعدة الحاسمة

**إعادة توليد زوج المفاتيح تُبطل كل التراخيص الصادرة سابقاً.** كل عميل سيحتاج
ترخيصاً جديداً. لا تفعل ذلك إلا إذا تسرّب المفتاح الخاص فعلاً.

**خذ نسخة احتياطية من `private-key.pem` الآن** — على وسيط مشفّر خارج الجهاز
(فلاشة مشفّرة أو مدير كلمات سرّ). فقدانه يعني عدم قدرتك على إصدار أي ترخيص جديد
أو تجديد أي ترخيص لأي عميل، والحلّ الوحيد حينها هو إصدار مفتاح جديد وتحديث كل
العملاء.

## 2. إصدار ترخيص لعميل

استلمت `activation-request-LAU-….json` من العميل:

```bash
node dist/cli.js issue \
  --request ~/Downloads/activation-request-LAU-143D-04DB-8E71.json \
  --customer "مغسلة النور" \
  --company "Al-Noor Laundry" \
  --type professional \
  --days 365
```

المخرجات:

```
✓ صدر الترخيص وتحقّقنا من توقيعه
  الملفّ    : issued/مغسلة_النور-professional.license
  العميل    : مغسلة النور (Al-Noor Laundry)
  النوع     : professional
  الجهاز    : LAU-143D-04DB-8E71
  الانتهاء  : 2027-08-01
  الحدود    : مستخدمون=5 أجهزة=3 فروع=غير محدود
  المزايا   : backup, offline_sync, multi_branch, reports_advanced
  المعرّف   : 0599e85c-e527-4a52-ae26-73a08622f7ff
```

أرسل الملفّ للعميل. هذا كل شيء.

> الـ CLI يُخرج بامتداد `.license` والمدير الرسومي بامتداد `.lkey` (التجاري في
> v2.0). التطبيق يقبل الاثنين، فلا ينكسر عميل سبق تسليمه.

> الأداة **تتحقّق من التوقيع بنفسها قبل الإخراج**، فلا يصل للعميل ملفّ لا يعمل.

### الخيارات

| الخيار | الوصف |
|---|---|
| `--request <ملفّ>` | **مطلوب** — طلب التفعيل من العميل |
| `--customer <اسم>` | **مطلوب** — اسم العميل |
| `--company <اسم>` | اسم الشركة |
| `--type` | `trial` \| `starter` \| `professional` \| `enterprise` |
| `--days N` | صلاحية بالأيام |
| `--expiry <ISO>` | تاريخ انتهاء صريح (بديل عن `--days`) |
| `--users N` `--devices N` `--branches N` | تجاوز حدود النوع (`-1` = غير محدود) |
| `--min-version 2.0` | أدنى إصدار تطبيق يقبل الترخيص |

بلا `--days` ولا `--expiry` ⇒ **ترخيص دائم**.

### فحص ترخيص

```bash
node dist/cli.js inspect issued/مغسلة_النور-professional.license
```

يطبع الحمولة كاملة وحالة التوقيع — مفيد عند شكوى عميل.

## 3. سير عمل التجديد

عند انتهاء ترخيص عميل:

1. اطلب منه تصدير طلب تفعيل **جديد** (البصمة قد تكون تغيّرت).
2. أصدر ترخيصاً جديداً بنفس الأمر مع `--days` جديدة.
3. أرسله — يستورده فيحلّ محلّ القديم.

لا حاجة لإلغاء القديم؛ التاريخ يتكفّل بذلك.

## 4. الأمان التشغيلي

**افعل:**
- احتفظ بنسخة احتياطية مشفّرة من `private-key.pem` خارج الجهاز.
- سجّل التراخيص الصادرة (العميل / `licenseId` / معرّف الجهاز / تاريخ الانتهاء) في
  جدول خاصّ بك — لا يوجد خادم يفعل ذلك نيابةً عنك.
- أصدر ترخيصاً لكل جهاز على حدة.

**لا تفعل:**
- لا تضع `private-key.pem` في Git ولا في أي مجلّد مشترك سحابي غير مشفّر.
- لا ترسل المفتاح الخاص لأي عميل تحت أي ظرف.
- لا تنسخ ملفّات المولّد داخل `apps/` — الفصل هو الحماية.

### التحقّق قبل كل إصدار

```bash
# لا مفتاح خاص في أي شيء يُشحن
grep -rl "BEGIN PRIVATE KEY" apps/ packages/ --exclude-dir=node_modules

# المفتاح الخاص متجاهَل فعلاً
git check-ignore -v tools/license-generator/keys/private-key.pem

# لا شيء غير متوقَّع سيُلتزم
git status --porcelain --untracked-files=all tools/
```

## 6. مدير التراخيص (واجهة رسومية) — الطريقة الموصى بها

الـ CLI أعلاه يبقى صالحاً، لكن للعمل اليومي استخدم المدير الرسومي:

```bash
pnpm run license:manager
# ثم افتح http://127.0.0.1:7788
```

يشارك **نفس** زوج المفاتيح مع الـ CLI — لا مفتاح خاص ثانٍ.

| التبويب | الوظيفة |
|---|---|
| السجلّ | كل التراخيص، بحث بالاسم أو معرّف الجهاز أو رقم الفاتورة، تنزيل، تجديد، إلغاء |
| إصدار ترخيص | الصق طلب التفعيل واملأ البيانات — يُنزَّل ملفّ `.lkey` تلقائياً |
| فحص ملفّ | يتحقّق من أي ترخيص بنفس منطق التطبيق — للتشخيص عند شكوى عميل |

### أين تُحفظ البيانات؟

```
tools/license-manager/data/registry.json   سجلّ التراخيص  (متجاهَل في Git)
tools/license-manager/data/issued/         ملفّات .lkey   (متجاهَل في Git)
tools/license-manager/data/backups/        نسخ السجلّ (آخر 30)
```

الكتابة **ذرّية** (ملفّ مؤقت ثم إعادة تسمية)، وتُؤخذ نسخة قبل كل تعديل.
**خذ نسخة احتياطية من `data/` مع نسخة المفتاح الخاص** — هو سجلّ عملائك الوحيد.

### الأمان

يُصغي على `127.0.0.1` فقط ولا يتصل بأي شبكة خارجية. لا تُشغّله على جهاز مشترك،
ولا تفتح المنفذ للشبكة.

### حدّ الإلغاء — اقرأه قبل أن تعد عميلاً بشيء

الإلغاء يُسجَّل **في سجلّك المحلّي فقط**. لا توجد قناة تصل لجهاز عميل مُفعَّل في
نظام يعمل دون إنترنت، فالترخيص المُسلَّم يبقى صالحاً على جهازه **حتى تاريخ
انتهائه**. فائدة الإلغاء: يمنع المدير تجديده، ويظهر بوضوح في السجلّ والبحث.

**النتيجة العملية:** إن كنت تحتاج قدرة فعلية على إيقاف عميل، أصدر تراخيص محدودة
المدّة (سنوية مثلاً) بدل الدائمة — عدم التجديد حينها هو آلية الإيقاف الحقيقية.
