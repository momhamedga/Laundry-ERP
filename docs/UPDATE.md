# التحديث التلقائي (Auto Update)

> عبر GitHub Releases · `electron-updater` · لا يمسّ البيانات ولا الترخيص ولا إعداد التشغيل

---

## 1. كيف يعمل

```
تشغيل البرنامج
   └─ فحص تلقائي (إن توفّر إنترنت)
        └─ تنزيل latest.yml من قناة الإصدارات
             ├─ الإصدار = الحالي  ⇒ لا شيء
             └─ الإصدار أحدث      ⇒ إشعار للمستخدم
                  └─ المستخدم يضغط «تنزيل»  ← لا تنزيل تلقائي
                       └─ تنزيل + تحقّق SHA-512
                            └─ «تثبيت وإعادة تشغيل»
```

**التنزيل لا يبدأ تلقائياً** (`autoDownload = false`) — المستخدم يقرّر، فلا
يُستهلك اتصال مغسلة أثناء ساعات العمل.

**المحدّث معطّل في التطوير** وفي أي نسخة غير مُغلَّفة (`app.isPackaged`).

---

## 2. `latest.yml`

يُولَّد آلياً مع كل بناء ويُرفع مع الأصول:

```yaml
version: 2.0.0
files:
  - url: Laundry-ERP-2.0.0-x64.exe
    sha512: <base64>
    size: 256814416
path: Laundry-ERP-2.0.0-x64.exe
sha512: <base64>
releaseDate: '2026-08-04T…'
```

### 🔴 قاعدة الاسم — سبب عطل حقيقي

`artifactName` **يجب ألّا يحوي مسافات**.

`${productName}` يحوي مسافة («Laundry ERP»)، وelectron-builder يكتب في
`latest.yml` اسماً مُعقَّماً بشرطات لا يطابق اسم الملفّ، **وGitHub يستبدل
المسافات بنقاط عند الرفع**. النتيجة: المحدّث يطلب ملفّاً غير موجود ⇒ **404**.

حدث فعلاً في **v1.3.1** واحتاج إعادة تسمية الأصول يدوياً عبر واجهة GitHub
البرمجية. أُصلح في Phase 15C بتثبيت الاسم:

```js
artifactName: `Laundry-ERP-${version}-${arch}.${ext}`   // بلا مسافات
```

**تحقّق قبل كل نشر:**

```bash
node -e "
const fs=require('fs'),crypto=require('crypto'),path=require('path');
const R='apps/desktop/release';
const yml=fs.readFileSync(path.join(R,'latest.yml'),'utf8');
const url=(yml.match(/url: (.+)/)||[])[1];
const declared=(yml.match(/^sha512: (.+)$/m)||[])[1];
const buf=fs.readFileSync(path.join(R,url));
console.log('الملفّ موجود :', fs.existsSync(path.join(R,url)));
console.log('SHA-512 مطابق:', declared===crypto.createHash('sha512').update(buf).digest('base64'));
console.log('بلا مسافات   :', !/\s/.test(url));
"
```

## 3. `blockmap`

`Laundry-ERP-<version>-x64.exe.blockmap` يتيح **التحديث التفاضلي**: يُنزَّل ما
تغيّر من كتل الملفّ فقط بدل 245 MB كاملة. يجب رفعه مع المُثبِّت.

بدونه يعمل التحديث لكن يُنزَّل الملفّ كاملاً.

---

## 4. الأصول المطلوبة في كل إصدار

| الأصل | إلزامي | الغرض |
|---|---|---|
| `Laundry-ERP-<v>-x64.exe` | ✅ | المُثبِّت |
| `latest.yml` | ✅ | بيان التحديث |
| `Laundry-ERP-<v>-x64.exe.blockmap` | مُوصى | التحديث التفاضلي |
| `Laundry-ERP-<v>-portable.exe` | اختياري | نسخة بلا تثبيت |

> **الوسم يجب أن يطابق الإصدار:** `v2.0.0` ↔ `version: 2.0.0`.

---

## 5. ما لا يتأثّر بالتحديث

| المكوّن | الحالة بعد التحديث |
|---|---|
| قاعدة البيانات المحلّية المشفّرة | سليمة |
| إعداد التشغيل (`server.env`) | **سليم** — خارج مجلّد التثبيت |
| أسرار JWT | **لا تُعاد توليدها** ⇒ الجلسات لا تنتهي |
| الترخيص (`license.dat`) | سليم |
| النسخ الاحتياطي والإعدادات | سليمة |

هذا مُتحقَّق منه عملياً: إلغاء تثبيت ثم إعادة تثبيت أبقت بصمة `server.env`
و`installId` **دون أي تغيير**.

## 6. الترقيم (Versioning)

`MAJOR.MINOR.PATCH` — وثلاثة ملفّات يجب أن تتطابق:

```
branding.config.json → product.version     ← المصدر الوحيد
apps/desktop/package.json → version        ← يُشتقّ آلياً (prepare-branding)
CHANGELOG.md → أحدث قسم
```

مرشّحات الإصدار: `2.0.0-rc1` — **لا تُنشر على القناة العامّة** كي لا يُرقّى
عملاء الإنتاج إلى نسخة اختبارية.

---

## 7. التراجع (Rollback)

**لا يوجد تراجع تلقائي.** `electron-updater` لا يدعمه.

عند وجود عطل في إصدار منشور:

1. **أزل الأصول** من الإصدار المعطوب على GitHub (يتوقّف ترقية العملاء فوراً).
2. أعد نشر الإصدار السابق كـ latest، **أو** أصدر إصلاحاً بترقيم أعلى (مُفضَّل).
3. للعميل المتضرّر: أرسل مُثبِّت الإصدار السليم — التثبيت فوقه يعمل، **وبياناته وإعداده وترخيصه سليمة**.

> رفع رقم الإصدار أفضل من الرجوع للخلف: `electron-updater` يقارن الإصدارات،
> فنشر رقم أقل لا يُرقّي من رقّى بالفعل.

---

## 8. التحديث دون إنترنت

المغاسل التي لا إنترنت لديها لا تتلقّى تحديثات تلقائية. الإجراء:

1. حمّل المُثبِّت الجديد على فلاشة.
2. شغّله فوق التثبيت القائم — **لا يحتاج إزالة أولاً**.
3. البيانات وإعداد التشغيل والترخيص كلها سليمة.

**لا حاجة لإعادة تجهيز ولا لإعادة استيراد الترخيص.**

---

## 9. التشخيص

| العَرَض | السبب المحتمل | الحل |
|---|---|---|
| «لا يوجد تحديث» رغم نشر إصدار | الوسم أو `latest.yml` لا يطابق | راجع تطابق الإصدار |
| فشل التنزيل 404 | اسم الأصل فيه مسافة أو GitHub أعاد تسميته | راجع §2 |
| فشل التحقّق من السلامة | `sha512` لا يطابق الملفّ المرفوع | أعد توليد `latest.yml` وارفع معاً |
| لا يفحص إطلاقاً | نسخة غير مُغلَّفة أو المحدّث معطّل | يعمل في النسخة المُثبَّتة فقط |

**السجلّ:** مساعدة ← فتح مجلد السجلّات ← ابحث عن `updater`.
